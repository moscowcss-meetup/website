# MoscowCSS — сайт сообщества

Исходники [css.moscow](https://css.moscow): сайта московского сообщества фронтендеров MoscowCSS. Здесь архив
всех митапов с 2017 года, доклады, спикеры, записи, слайды и фото. Сайт статический, собирается на
[Astro](https://astro.build) и сам выкладывается на GitHub Pages после каждого изменения в `main`.

Весь текст сайта лежит обычными Markdown-файлами. Чтобы добавить ссылку на видео или поправить описание
доклада, программировать не нужно.

## Как помочь

Архив неполный. Цель:

- у каждого доклада есть отдельный ролик на YouTube;
- у каждого доклада есть отдельный ролик в VK Видео;
- у каждого доклада есть ссылка на слайды;
- у каждого митапа есть фото на странице;
- у каждого митапа есть ссылка на фотоальбом в ВК или на Яндекс Диске, лучше оба.

Что уже есть и чего не хватает, видно в задачах:

- **[Общий план #14](https://github.com/moscowcss-meetup/website/issues/14)**: цель и список задач.
- [Помочь с контентом](https://github.com/moscowcss-meetup/website/labels/%D0%BA%D0%BE%D0%BD%D1%82%D0%B5%D0%BD%D1%82): по задаче на
  каждый митап, внутри чек-лист по докладам. Можно отфильтровать по
  [видео](https://github.com/moscowcss-meetup/website/labels/%D0%B2%D0%B8%D0%B4%D0%B5%D0%BE),
  [фото](https://github.com/moscowcss-meetup/website/labels/%D1%84%D0%BE%D1%82%D0%BE) и
  [слайдам](https://github.com/moscowcss-meetup/website/labels/%D0%BF%D1%80%D0%B5%D0%B7%D0%B5%D0%BD%D1%82%D0%B0%D1%86%D0%B8%D0%B8).
- [Разработка](https://github.com/moscowcss-meetup/website/labels/%D1%80%D0%B0%D0%B7%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%BA%D0%B0): доработки
  самого сайта.
- Сводные таблицы: [митапы](docs/todo/meetups.md) и [доклады](docs/todo/talks.md). Их пересобирает
  `pnpm report:content`, где искать записи — в [sources.md](docs/todo/sources.md).

### Как взять задачу

1. Выберите задачу без исполнителя: в списке задач фильтр **Assignee → No assignee**.
2. Назначьте её на себя: в правой колонке задачи **Assignees → assign yourself**. Так все видят, что
   задача занята, и никто не делает её вдвоём. Кнопки нет у тех, кто не в команде репозитория: тогда
   напишите в комментарии «беру», и организатор назначит вас. Хотите сделать только один пункт
   чек-листа, а не весь митап, — напишите в комментарии, какой.
3. Сделайте, как описано ниже, и отметьтесь в задаче: ссылкой на pull request или просто ссылкой в
   комментарии, если не хочется возиться с GitHub. Организаторы перенесут её на сайт.
4. Передумали или не успеваете — снимите себя с задачи, это нормально.

Вопросы — в [чат сообщества](https://t.me/moscowcss_chat) или в комментарии к задаче.

### Добавить ссылку на видео, слайды или альбом

Ссылка — одна строка в шапке (frontmatter) файла. Править можно прямо на GitHub: откройте файл, нажмите
карандаш, поправьте и отправьте изменение, GitHub сам предложит pull request.

| Что | Файл | Поле |
| --- | --- | --- |
| Ролик доклада | `packages/content/src/talks/ru/<доклад>.md` и `…/en/<доклад>.md` | `videoUrl` |
| Слайды доклада | там же | `slidesUrl` |
| Полная запись митапа | `packages/content/src/events/ru/<номер>.md` и `…/en/<номер>.md` | `recordingUrl` |
| Фотоальбом митапа ВКонтакте | там же | `vkPhotosUrl` |
| Папка с фото на Яндекс Диске | там же | `diskPhotosUrl` |

```yaml
videoUrl: "https://www.youtube.com/watch?v=…"
slidesUrl: "https://…"
```

Правила:

- значение одинаковое в `ru` и `en`, сборка это проверяет;
- только `https://` ссылки;
- если у доклада нет своего ролика, а у митапа есть полная запись, на странице доклада уже стоит ссылка
  «Запись митапа». Ссылка с таймкодом (`…&t=1000s`) в `videoUrl` лучше, отдельный ролик ещё лучше.

### Нарезать запись митапа на доклады

Полные записи многих митапов есть, а отдельных роликов по докладам нет. Как помочь:

1. Возьмите полную запись из задачи митапа и отметьте начало и конец каждого доклада. Уже одни
   таймкоды полезны: пришлите их в комментарии.
2. Вырежьте доклад любым редактором или `ffmpeg` без перекодирования:

   ```bash
   ffmpeg -ss 00:16:40 -to 00:36:50 -i meetup.mp4 -c copy talk.mp4
   ```

3. Загрузите файл на Яндекс Диск или в другое облако и оставьте ссылку в комментарии к задаче. Название
   ролика — как на канале: «Название доклада. Имя Фамилия».
4. Организаторы зальют ролик на [YouTube-канал @Moscowcss](https://www.youtube.com/@Moscowcss) и в VK
   Видео и добавят ссылки в доклад, или ответят ссылками, чтобы добавили вы.

### Добавить фото митапа

1. Выберите 5–8 лучших снимков шириной до 2000 пикселей.
2. Положите их в `packages/content/src/events/assets/<номер>-1.jpg`, `<номер>-2.jpg` и так далее.
3. Перечислите их в `gallery` в обоих файлах митапа. Путь одинаковый, а описание `alt` на своём
   языке: что на снимке, для тех, кто его не видит.

```yaml
gallery:
  - image: ../assets/18-1.jpg
    alt: "Спикер у экрана со слайдом о контейнерных запросах"
```

Если проще, пришлите ссылку на папку со снимками в комментарии к задаче.

### Поправить описание, добавить фото спикера

Описание доклада — текст под шапкой файла доклада, в `ru` и `en` свои формулировки. Фото спикера, его
роль и ссылки — в `packages/content/src/speakers/`. Все поля и примеры:
[как писать контент](packages/content/README.md).

## Где что лежит

```
apps/
  website/          сайт на Astro: страницы, разделы, SEO, поиск, проверки
  storybook/        витрина компонентов
packages/
  content/          весь контент: митапы, доклады, спикеры, партнёры, ЧАВО, отзывы (.md, ru и en)
  ui/               компоненты Astro и их стили
  design-system/    дизайн-токены: цвета, отступы, типографика, брейкпоинты
  og/               картинки для соцсетей, обложки докладов, аватары, иконки
  icons/            SVG-иконки, из которых собираются компоненты
  fonts/            шрифты
  eslint-config/    общие настройки ESLint
  typescript-config/ общие настройки TypeScript
tools/              визуальные снимки, проверка доступности и областей нажатия, вырезание фона
docs/               развёртывание и списки того, что нужно дополнить (docs/todo)
adr/, specs/        архитектурные решения и спецификации
```

Контент: `packages/content/src/<коллекция>/<язык>/<имя>.md`, картинки — в `assets/` рядом с
коллекцией. Связи пишутся только в докладе (`event`, `speakers`): программа митапа и список докладов
спикера собираются при сборке. Подробно — в [README контента](packages/content/README.md).

## Запуск локально

Нужны Node.js LTS (версия в `.nvmrc`) и pnpm через Corepack.

```bash
corepack enable
pnpm install
pnpm dev:site        # сайт на http://localhost:4321
```

| Команда | Что делает |
| --- | --- |
| `pnpm dev` | сайт и Storybook вместе |
| `pnpm build` | сборка сайта и поискового индекса; проверяет контент и называет файл и поле с ошибкой |
| `pnpm test` | тесты всех пакетов |
| `pnpm lint` | ESLint с автоисправлением |
| `pnpm new:talk <имя>` | заготовка доклада в `ru` и `en`; есть `new:event`, `new:speaker` и другие |
| `pnpm report:content` | пересобирает таблицы `docs/todo` из контента |

Перед pull request должны проходить `pnpm lint`, `pnpm test` и `pnpm build`; то же самое запускает CI.
Сообщения коммитов — по [Conventional Commits](https://www.conventionalcommits.org/ru/) на английском:
`feat:`, `fix:`, `docs:`, `chore:`.

Правила для кода (токены вместо значений в стилях, тексты только из словаря или контента, комментарии
на русском) собраны в [CLAUDE.md](CLAUDE.md): он же инструкция для ИИ-агентов, у каждого пакета есть
свой. Развёртывание и домен — [docs/deploy.md](docs/deploy.md).
