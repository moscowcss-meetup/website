# @moscowcss/content — как писать контент

Весь контент сайта лежит здесь обычными файлами `.md`: страницы, митапы, доклады, спикеры, партнёры
и вопросы из блока «ЧАВО». Пишите Markdown: заголовки `##`, списки `-`, ссылки `[текст](https://…)`.
Другие форматы (`.mdx`, `.yml`, `.json`) не используются.

## Как добавить

Команды запускаются из корня репозитория. Каждая создаёт два черновика, `ru` и `en`, с `draft: true`:
на сайт они не попадают, пока вы не уберёте эту строку в обоих файлах. Править можно и прямо на
GitHub, см. «Правка с телефона», там файлы создаются вручную по тем же путям.

Проверить результат локально:

```bash
pnpm build                       # проверит контент и назовёт файл и поле с ошибкой
pnpm dev                         # запустит сайт локально
```

После слияния в `main` сайт обновляется сам. Кроме того, он пересобирается каждую ночь: прошедший
митап сам перестаёт быть ближайшим.

### Снежинки вместо пружинок

По сайту падают разноцветные пружинки. На зиму их можно поменять на снежинки одной строкой в
`pages/ru/index.md` и `pages/en/index.md`:

```yaml
decor: snow      # или springs
```

Посетитель сайта может только выключить их у себя чекбоксом в шапке или меню. Над текстом фигуры сами
становятся серыми и почти прозрачными, отдельно за этим следить не нужно.

### Текущего организатора

```bash
pnpm new:organizer anna-ivanova
```

1. Заполните `name` и `contacts` и напишите текст о человеке в `organizers/ru/anna-ivanova.md` и
   `organizers/en/anna-ivanova.md`.
2. Оставьте `status: current`.
3. Положите фото в `organizers/assets/anna-ivanova.png` и добавьте в оба файла строку `photo`,
   как в примере. Фото необязательно, подробности в разделе «Фото, слайды, видео и прочее: что куда».
4. Уберите `draft: true` из обоих файлов.

```yaml
---
name: "Анна Иванова"
status: current
photo: ../assets/anna-ivanova.png
contacts:
  telegram: https://t.me/anna_ivanova
  github: https://github.com/anna-ivanova
  website: https://anna.example
---

- Руководитель фронтенда в Компании
- Участница программного комитета
```

Текст о человеке — обычный Markdown под frontmatter, как удобнее: списком, абзацем или и тем и другим.
Пункты списка выводятся со значком `>`, как в макете. Текст необязателен.

Контакты выводятся только заполненные. Ненужную строку просто удалите; без контактов можно убрать
весь блок `contacts`. Адреса строгие: `https://t.me/<имя>` и `https://github.com/<имя>`, иначе сборка
упадёт и назовёт файл.

### Бывшего организатора

Всё то же самое, но `status: past`. Если человек уже есть в коллекции, поменяйте `current` на `past`
в обоих языках: остальное править не нужно.

Сейчас на сайте показываются только текущие. Бывшие хранятся в тех же файлах для будущей страницы о
митапе, поэтому файлы можно заводить уже сейчас, на главной они не появятся.

### Отзыв

```bash
pnpm new:review anna-ivanova
```

1. Вставьте текст отзыва в `reviews/ru/anna-ivanova.md`, перевод в `reviews/en/anna-ivanova.md`. Текст
   человека не правим. На стикер попадает первый абзац, длинный обрезается по границе слова; весь
   текст открывается в окне.
2. Заполните `name` и `category`: кто оставил отзыв. `role` необязательна.
3. Портрет положите в `reviews/assets/anna-ivanova.jpg` и добавьте в оба файла строку `photo`. Без
   портрета на стикере будут инициалы.
4. Остальные снимки перечислите в `gallery`: они идут галереей в окне отзыва.
5. Уберите `draft: true` из обоих файлов.

Порядок на стене случайный при каждой загрузке. Ссылка на отзыв: `/reviews/?review=anna-ivanova`.
Пока нет ни одного опубликованного отзыва, страницы и ссылок на неё на сайте нет.

### Митап

```bash
pnpm new:event 32
```

1. Заполните `events/ru/32.md` и `events/en/32.md`: `date`, `time`, `tagline`, `venue`, `modes`,
   `passportRequired`. Дату, время и ссылки копируйте в оба языка один в один.
2. Добавьте `tags`: темы, которые падают плашками в верхней части главной.
3. Добавьте `registrationUrl`: с ним на главной появляется плавающая кнопка регистрации. Она видна,
   пока митап не прошёл, и сама исчезает после него.
4. Партнёра укажите полем `partner: zvuk`: это имя файла из `partners/`.
5. Уберите `draft: true` из обоих файлов.

Главная сама показывает ближайший будущий митап, а если такого нет, последний прошедший с пометкой
«Митап уже прошёл». После митапа добавьте `recordingUrl` и `photosUrl`.

### Доклад

```bash
pnpm new:talk anchor-and-popover
```

1. Заполните `title` и описание в тексте файла, в `ru` и `en` свои формулировки.
2. Укажите митап и спикеров, см. следующие разделы. Эти поля и `time` в обоих языках одинаковые.
3. Уберите `draft: true` из обоих файлов.

В программе доклады идут по `time`. В `schedule` митапа доклад добавлять не нужно: там только перерывы
и активности без спикера.

```yaml
---
event: "31"
speakers:
  - anna-rastorgueva
time: "21:00"
title: "БРОСАЕМ ЯКОРЬ. НОВАЯ ЭРА НАТИВНЫХ ТУЛТИПОВ И ПОПОВЕРОВ"
---

Описание доклада: о чём он и что узнают слушатели.
```

### Спикера

```bash
pnpm new:speaker anna-rastorgueva
```

1. Заполните `name` и `role` в обоих языках. Имя на английском пишется транслитом.
2. Положите фото в `speakers/assets/anna-rastorgueva.jpg` и добавьте в оба файла строки из примера.
   Без фото сайт нарисует аватар с инициалами.
3. Уберите `draft: true` из обоих файлов.

```yaml
photo: ../assets/anna-rastorgueva.jpg
```

Спикер заводится один раз. Если он выступает снова, новый файл не нужен: сошлитесь на него из
нового доклада.

### Как указать спикера на докладе

Только в файле доклада, в поле `speakers`: имя файла спикера без языка и расширения. Спикеров может
быть несколько:

```yaml
speakers:
  - daria-egorova
  - anna-rastorgueva
```

Наоборот не работает: **в файле спикера доклады не пишут**. Список докладов на его странице сайт
собирает сам из всех докладов, где он указан.

### Как указать, что доклад будет на конкретном митапе

Только в файле доклада, в поле `event`: номер митапа **в кавычках**. Это имя файла митапа.

```yaml
event: "32"
```

Чтобы перенести доклад на другой митап, поменяйте номер в обоих языках. В файле митапа ничего писать
не нужно: программа собирается сама.

Порядок заведения любой: черновик доклада может ссылаться на ещё не созданные митап и спикера. У
опубликованного доклада они уже должны существовать и быть опубликованы, иначе сборка упадёт и
назовёт доклад.

### Фото, слайды, видео и прочее: что куда

Картинки лежат в папке `assets/` рядом с коллекцией, а не в папке языка: файл один на оба языка.
Имя файла — латиница в нижнем регистре, цифры и дефисы, лучше как у записи (`anna-lapa.jpg`). Путь в
поле одинаковый в `ru` и `en`, сборка это проверяет.

#### Фото спикера

1. Положите фото в `speakers/assets/<имя>.jpg` (или `.png`). Лучше квадрат от 500×500 с лицом в центре:
   на сайте фото обрезается восьмиугольником.
2. Добавьте в оба файла спикера строку `photo: ../assets/<имя>.jpg`.

Фото само попадает на страницу спикера, в программу митапа, в карточки и на обложки его докладов. Без
фото сайт рисует аватар с инициалами, а обложка доклада — надпись TBD. Описание к фото не пишется: имя
стоит рядом. Если спикер прислал фото с отзывом, можно взять его: скопируйте файл из `reviews/assets/`.

#### Текст «О спикере» и ссылки

- Текст файла спикера (под `---`) выходит на его странице блоком «О спикере», между фото и докладами.
  Пишите факты, которые дал сам спикер или анонс в канале: роль, где ещё выступает, хобби.
- Ссылки — список `links`, у каждой `label` и `url`:

```yaml
links:
  - label: "Telegram"
    url: "https://t.me/itsmirnov"
```

#### Обложка доклада

Отдельную картинку делать не нужно: сайт рисует обложку сам из названия доклада, имени спикера и его
фото — одну на все доклады в едином стиле. Она же уходит превью в соцсети. Чтобы на обложке было фото,
добавьте фото спикеру. Старое поле `cover` (карточка анонса) осталось в старых докладах, но на сайте не
показывается.

#### Слайды и запись доклада

В файле доклада, одинаково в обоих языках:

```yaml
slidesUrl: "https://…"
videoUrl: "https://…"
vkVideoUrl: "https://vkvideo.ru/video-…"
```

На странице доклада появятся кнопки «Слайды», «Запись доклада» и «VK Видео».
Если своего ролика у доклада нет, а у митапа есть `recordingUrl`, вместо «Записи доклада» стоит
кнопка «Запись митапа». Ссылка в `videoUrl` может вести на полную запись с таймкодом начала доклада
(`https://www.youtube.com/watch?v=…&t=1000s`), пока нет отдельного ролика.

#### Фото с митапа

1. Положите снимки в `events/assets/<номер>-1.jpg`, `<номер>-2.jpg` и так далее. Хватит 5–8 лучших,
   по ширине до 2000 пикселей.
2. Добавьте в файлы митапа список `gallery`. Путь одинаковый, а описание `alt` — на своём языке: что на
   снимке, для тех, кто его не видит.

```yaml
gallery:
  - image: ../assets/32-1.jpg
    alt: "Спикер у экрана со слайдом о контейнерных запросах"
```

На странице митапа снимки идут лентой и открываются крупно. Полный альбом — ссылкой в `photosUrl`,
запись всего митапа — в `recordingUrl`.

#### Фото к отзыву

Портрет — `reviews/assets/<имя>.jpg` и строка `photo: ../assets/<имя>.jpg`. Ещё снимки — список
`gallery` с `image` и `alt`, как у митапа: они открываются в окне отзыва.

#### Фото организатора

`organizers/assets/<имя>.png` и строка `photo: ../assets/<имя>.png`. Это вырезанный силуэт на
прозрачном фоне, квадрат от 500×500: непрозрачное фото закроет розовый восьмиугольник. Фон вырезает
`pnpm cutout <фото> <png> --preview`, см. `tools/cutout/README.md`.

#### Логотип партнёра

`partners/assets/<имя>.svg` (или `.png`) и строка `logo: ../assets/<имя>.svg`.

#### Темы митапа

Список `tags` в файле митапа — плашки, которые падают в верхней части главной. Это текст на своём
языке, переводить можно свободно.

## Раскладка

```
src/
  pages/<язык>/index.md          главная: описание сообщества
  events/<язык>/<номер>.md       митап; номер митапа — имя файла (31.md → 31-й митап)
  talks/<язык>/<имя>.md          доклад
  speakers/<язык>/<имя>.md       спикер
  speakers/assets/<имя>.jpg      фото спикеров, общие для всех языков
  partners/<язык>/<имя>.md       партнёр митапа
  organizers/<язык>/<имя>.md     организатор
  organizers/assets/<имя>.png    фото организаторов, общие для всех языков
  faq/<язык>/<имя>.md            вопрос и ответ из «ЧАВО»
  documents/<язык>/<имя>.md      отдельная страница: «О сообществе», «Контакты», памятка спикеру, политика обработки персональных данных
```

- `<язык>` — `ru` или `en`.
- `<имя>` — латиница в нижнем регистре, цифры и дефисы: `daria-egorova`, `gamification-in-business`.
  По имени файла другие файлы ссылаются на этот.
- **Перевод** — тот же путь в папке другого языка: `talks/ru/anchor-and-popover.md` и
  `talks/en/anchor-and-popover.md`. Переводятся тексты: заголовки, описания, подписи. Всё остальное
  одинаково в обоих языках (см. «Что должно совпадать»).

## Поля по коллекциям

Обязательные поля отмечены знаком «да». Если обязательное поле пропущено или записано неверно,
сборка упадёт и назовёт файл и поле.

### `pages` — главная

| Поле | Обязательное | Что |
|---|---|---|
| `title` | да | Заголовок страницы (`<title>`), до 70 символов. |
| `description` | да | Описание для поисковиков и соцсетей, 50–160 символов. |
| `telegramUrl` | да | Ссылка на телеграм-канал, `https://t.me/moscowcss`. |
| `questionTag` | да | Тег для вопросов спикерам, `"#вопрос_спикеру"` (в кавычках: без них YAML прочтёт `#` как комментарий). Его показывает подсказка программы; если тег написан в тексте FAQ, он должен совпадать — иначе сборка упадёт и назовёт файл. |
| `decor` | нет | Что падает по сайту: `springs` (по умолчанию) или `snow`. Одинаково в обоих языках. |
| текст файла | да | Абзац «о митапе». |

### `events` — митап

| Поле | Обязательное | Что |
|---|---|---|
| `date` | да | День митапа: `2026-07-09` (без времени). |
| `time` | да* | Начало по московскому времени: `"18:00"` (в кавычках). Часовой пояс писать не нужно. *Пропускается только у митапов 2017 года (1–6): их время не сохранилось ни в одном источнике, и сайт показывает одну дату. У нового митапа время есть всегда. |
| `tagline` | да | Подпись под заголовком: «32 митап сообщества разработчиков интерфейсов в Школе 21». В архиве прошлых митапов подписи остаются как были. |
| `venue.name` | да | Название площадки. |
| `venue.address` | да* | Адрес одной строкой. *Пропускается только у митапов 2017 года (1–6): в источниках есть площадка, но не адрес. |
| `venue.mapUrl` | нет | Ссылка на карту. |
| `venue.coordinates` | нет | `latitude`, `longitude`, `zoom` — точка на карте. |
| `modes` | да | Список форматов: оффлайн, онлайн, бесплатно. |
| `tags` | нет | Темы митапа, они падают плашками в верхней части главной: `- "popover api"`. Тему с решёткой пишут в кавычках: `"#вопрос_спикеру"`. Список переводится вместе с текстом, в `en` свои формулировки. Нет тем — нет плашек. |
| `passportRequired` | да | `true`, если вход по паспорту. |
| `registrationUrl` | нет | Ссылка на регистрацию. |
| `streamUrl` | нет | Ссылка на трансляцию. Пока её нет, поле не пишут. |
| `recordingUrl` | нет | Ссылка на запись после митапа. |
| `photosUrl` | нет | Ссылка на фотоальбом митапа (VK, Яндекс Диск). Сами фотографии на сайт не копируются. |
| `partner` | нет | Имя файла партнёра: `zvuk`. |
| `gallery` | нет | Снимки со встречи: `image` (файл в `events/assets/`) и `alt` (что на снимке). Первый снимок на странице митапа крупный, по клику любой открывается во весь экран. Файлы в языках одинаковые. |
| `schedule` | нет | Перерывы и активности без спикера: `title`, `kind` (`break` или `activity`), `time`. Время можно не писать, пока расписание не готово: тогда сначала идут доклады, потом пункты в порядке файла. |
| `draft` | нет | `true` — черновик. |
| текст файла | нет | Дополнительный текст о митапе: подсказки, как добраться. |

Время в `schedule` — `19:40—20:00` (интервал) или `19:40`. Доклады в `schedule` не пишут: они
собираются в расписание из файлов `talks`.

### `talks` — доклад

| Поле | Обязательное | Что |
|---|---|---|
| `event` | да | Номер митапа **в кавычках**: `"31"`. Без кавычек сборка упадёт. |
| `speakers` | да | Список имён файлов спикеров: `- daria-egorova`. Спикеров может быть несколько. |
| `time` | нет | Начало доклада, `19:10` (в кавычках). Нет у докладов архивных митапов — время не сохранилось; такие доклады идут в программе после докладов со временем. |
| `title` | да | Название доклада. |
| `slidesUrl` | нет | Ссылка на слайды. |
| `videoUrl` | нет | Ссылка на видео, обычно YouTube. |
| `vkVideoUrl` | нет | Ссылка на тот же доклад в VK Видео: `vk.com`, `vk.ru` или `vkvideo.ru`, другие адреса сборка не пропустит. |
| `cover` | нет | Старая карточка анонса из Telegram в `talks/assets/`. На сайте не показывается: обложку каждого доклада сайт рисует сам в одном стиле — название, спикер, метка митапа и фото спикера (без фото — TBD). |
| `draft` | нет | `true` — черновик. |
| текст файла | да | Описание доклада. |

### `speakers` — спикер

| Поле | Обязательное | Что |
|---|---|---|
| `name` | да | Имя и фамилия. |
| `role` | нет | Должность и место работы. Нет у спикеров первых митапов — не сохранилась; тогда сайт её не показывает. |
| `photo` | нет | Путь к фото: `../assets/<имя>.jpg`. Файл лежит в `speakers/assets/`. Без фото сайт рисует аватар с инициалами. |
| `links` | нет | Список ссылок: `label` (подпись) и `url`. |
| `founder` | нет | `true` — основатель сообщества: плашка «Основатель» своего фиолетового цвета на странице спикера и у его отзыва. Одинаково в обоих языках. |
| `draft` | нет | `true` — черновик. |

### `documents` — служебный документ

Открывается по адресу `/<имя>/` (`/about/`, `/help/`, `/privacy/`, `/speaker-guide/`; на английском — под `/en/`). Контакты — карточки из поля `contacts` в `about.md`: заголовок, текст и ссылки-кнопки. С полем `contacts` документ свёрстан как страница «О сообществе»: факты, цифры (их сайт считает сам), лента фото с последних митапов, текст и карточки.

| Поле | Обязательное | Что |
|---|---|---|
| `title` | да | Заголовок страницы, до 70 знаков. |
| `description` | да | Описание для поисковиков и карточки, 50–160 знаков. |
| текст файла | да | Текст документа в Markdown. |
| `facts` | нет | Короткие факты через слеш под заголовком: «С 2015 года», «Москва и онлайн». |
| `contacts` | нет | `lead` (вступление) и `items`: у каждой карточки `title`, `text` и `links` (`label` + `url`). Ссылка на памятку и чужие сайты открываются в новой вкладке. |
| `help` | нет | С ним документ свёрстан как страница «Как помочь митапу» (`help.md`): `needs` (`title` и карточки `items`, как у `contacts`, с номерами 01, 02…), `reach` (`title`, `lead` и `items` с `value`, `label`, необязательной `note`: цифры охвата пишутся руками, рядом сайт сам ставит число митапов, докладов и спикеров), `offer` (`title` и пункты `items`), `venues` (`title` и `text`: площадки сайт собирает из митапов и роняет кучей, как темы в Hero) и `contact` (чёрный блок: `title`, `text`, `links`). |
| `topics` | нет | Раскрывающийся список в конце страницы: `summary` (заголовок) и `items` (пункты, простым текстом). В памятке спикеру это примеры тем. |
| `draft` | нет | `true` — черновик. |

### `partners` — партнёр

| Поле | Обязательное | Что |
|---|---|---|
| `name` | да | Название. |
| `handle` | да | Адрес в телеграме, `@ZVUK_JOBS`. |
| `url` | нет | Ссылка на партнёра. |
| `logo` | нет | Логотип: `../assets/<имя>.svg` (или `.png`) в `partners/assets/`. Без него выводится название. |
| `qrUrl` | нет | Адрес для QR-кода под логотипом (`https://…`). QR сайт рисует сам. |
| `tagline` | да | Короткое описание. |
| `features` | да | Карточки: `title`, `description` — обязательные, `footnote` (сноска) — нет. |
| `draft` | нет | `true` — черновик. |

У партнёра есть необязательное поле `look`: `default` или `school21` (свой блок в стиле Школы 21: `SchoolPartnerSection`), одинаковое в языках. Текст файла партнёра необязателен: он выводится рассказом под заголовком блока.

### `organizers` — организатор

| Поле | Обязательное | Что |
|---|---|---|
| `name` | да | Имя и фамилия. |
| `status` | да | `current` — текущий организатор, он показывается на главной; `past` — бывший. |
| `photo` | нет | Фото: `../assets/<имя>.png` в `organizers/assets/` (прозрачный фон, вырезанный силуэт). Без фото блок фото на карточке не выводится. |
| `contacts` | нет | `telegram` (`https://t.me/<имя>`), `channel` (канал, `https://t.me/<имя>`), `github` (`https://github.com/<имя>`), `website` (любой `https`): все необязательные. На карточке выводятся в этом порядке и только заполненные. |
| `draft` | нет | `true` — черновик. |
| текст файла | нет | Должность, роли в сообществах: Markdown, список или абзац. |

Новый организатор появляется на главной без правки кода: достаточно файлов в обоих языках со статусом `current`.

Порядка у организаторов нет: они равноправны. На главной карточки идут слайдером: порядок случайный при
каждой загрузке, раз в пять секунд лента сама сдвигается на одну карточку и идёт по кругу.

### `reviews` — отзыв о сообществе

| Поле | Обязательное | Что |
|---|---|---|
| `name` | да | Имя и фамилия автора. |
| `speaker` | нет | Имя файла спикера (`anna-lapa`), если автор выступал: шапка окна отзыва ведёт на его страницу. Одинаково в языках. |
| `category` | да | Кто оставил отзыв: `speaker` — спикер, `organizer` — текущий организатор, `past-organizer` — бывший организатор, `guest` — гость, `partner` — партнёр. По ней работает фильтр на стене. |
| `role` | нет | Должность и компания: только если автор её назвал. |
| `photo` | нет | Портрет: файл в `reviews/assets/`. Без него сайт рисует инициалы. |
| `gallery` | нет | Снимки в окне отзыва: у каждого `image` (файл в `reviews/assets/`) и `alt` (что на снимке). |
| `draft` | нет | `true` — черновик. |
| текст файла | да | Отзыв: Markdown. Первый абзац показывается на стикере. |

### `faq` — вопрос из «ЧАВО»

| Поле | Обязательное | Что |
|---|---|---|
| `title` | да | Вопрос, заглавными буквами, как на карточке. |
| `order` | да | Порядок карточек: 1 — первая слева. |
| текст файла | да | Ответ в Markdown. |
| `draft` | нет | `true` — черновик. |

В ответе перенос строки пишите обратной косой чертой в конце строки (`\`): без неё две строки
склеятся. Строку, которая начинается с «1.», начинайте с `1\.`, иначе Markdown сделает из неё список.
Звёздочку `*` в тексте пишите как `\*`.

## Ссылки и текст

Все ссылки — только `https://…`: сборка не пропустит `http:`, `javascript:` и `data:`. Текст файла —
только Markdown: HTML-теги (`<div>`, `<img>`, `<script>`) сборка отклоняет. HTML-комментарий `<!-- … -->` — тоже
HTML: пояснения пишите в frontmatter строкой с `#`.

Митап считается идущим ещё 4 часа после начала: пока он идёт, главная показывает его как ближайший.

## Связи

Связь хранится только в докладе: `event: "31"` и `speakers: [daria-egorova]`. Список докладов
митапа и список докладов спикера сайт собирает сам, их не пишут. Имена в связях — это имена файлов
без языка и расширения. Если такого файла нет в том же языке, сборка упадёт и назовёт доклад — у опубликованного доклада; черновик может ссылаться на ещё не заведённые записи.

## Что должно совпадать между языками

Эти поля в переводе копируются из русской версии один в один, и сборка проверяет, что они не
разошлись:

- митап: `date`, `time`, `passportRequired`, `venue.mapUrl`, `venue.coordinates`, `registrationUrl`,
  `streamUrl`, `recordingUrl`, `photosUrl`, `partner`, время и `kind` в `schedule`;
- доклад: `event`, `speakers`, `time`, `slidesUrl`, `videoUrl`, `cover`;
- спикер: `photo`, `links`;
- партнёр: `url`, `handle`, `logo`, `qrUrl`;
- организатор: `status`, `photo`, `contacts`;
- отзыв: `category`, `photo`, файлы `gallery`;
- вопрос FAQ: `order`;
- главная: `telegramUrl`, `questionTag`, `decor`.

Поменяли дату или спикера — поправьте оба языка.

## Черновик

`draft: true` оставляет митап, доклад, спикера, партнёра, организатора или вопрос FAQ в репозитории, но прячет с сайта. Схема при этом
всё равно проверяется. Полей нет — значит `draft: false`, опубликовано. Языки публикуются
независимо.

## Правка с телефона

1. Откройте github.com и найдите нужный файл в `packages/content/src/…`.
2. Нажмите карандаш («Edit this file»).
3. Поправьте текст и нажмите **Commit changes**.
4. Дождитесь сборки сайта: если в файле ошибка, в логе будет его путь и название поля.

Перевод правится отдельным файлом по тому же пути в другой папке языка.

## Новые файлы

Заготовки создают команды из корня репозитория:

```bash
pnpm new:event 32                         # номер митапа
pnpm new:talk gamification-in-business
pnpm new:speaker daria-egorova            # без фото: на сайте будет аватар с инициалами
pnpm new:partner zvuk
pnpm new:faq afterparty
pnpm new:organizer roman-troitsky
```

Команда создаёт файлы сразу в `ru/` и `en/` и ничего не перезаписывает: если хоть один файл уже
есть, она назовёт его и не создаст ничего. Все заготовки появляются с `draft: true`;
заполните значения (подсказки — строки с `#` во frontmatter заготовки, их можно оставить), добавьте фото спикера, если оно есть, и
уберите `draft: true`. Партнёр и вопрос FAQ тоже создаются черновиками; опубликованный митап не может ссылаться на партнёра-черновика.
Шаблоны лежат в `packages/content/templates/`.
